# 정정 — FOCUS 비교는 재현이 아니었다 + 관련도는 연속적이다

2026-08-25. GPU 미사용, 기존 로그의 오프라인 재계산.

## 1. 정정: docs/34·37의 "FOCUS식"은 FOCUS가 아니었다

**FOCUS 원 알고리즘** (arXiv 2508.13744, 원문 확인):

```
ℓ_final = Σ_{i=1..N} ( ℓ_i − α · ℓ_noise )
  ℓ_i     : 이미지 i만 깨끗하게 두고 **나머지 전부**를 노이즈로 덮은 입력의 logit
  ℓ_noise : 전 이미지를 노이즈로 덮은 입력의 logit
  노이즈  : v' = (1−λ)·v + λ·U(0,1),  α·λ 는 벤치마크별 validation 튜닝
```

**FOCUS는 유/무관 이미지를 구분하지 않는다.** 모든 이미지를 각각 고립시켜 보고 **전부 합산**한다.
버리는 이미지가 없고, 이산 판정이 없다.

우리가 `38_baselines.py`에서 만든 `FKEEP`는 **argmax로 하나를 골라 나머지를 노이즈로 덮은 것**으로,
FOCUS의 per-image pass 하나에 우리 선택 규칙을 얹은 **우리 발명**이다. FOCUS가 아니다.

→ docs/34·37의 "FOCUS식 직접 비교" 표는 **"우리 레시피에서 개입 수단만 교체한 ablation"**으로
   이름을 바꾼다. "FOCUS를 이겼다"는 표현은 그 표에 근거할 수 없다.

## 2. 정식 FOCUS 재구성 — 이미지 2장 조건에서는 정확히 가능

2장에서는 우리 로그가 FOCUS의 모든 항을 담고 있다:
`FN1`(이미지1 노이즈) = ℓ_0, `FN0`(이미지0 노이즈) = ℓ_1, `ALLN` = ℓ_noise.

α는 −0.2~1.0 스윕 후 **FOCUS에 가장 유리한 값**을 선택했다.

| | 기준선 | **FOCUS (정식, 최적 α)** | **우리 (실현)** | 상한 | 우리−FOCUS 95%CI |
|---|---|---|---|---|---|
| 3B | 0.6970 | 0.5826 (α=1.0) | **0.7556** | 0.9057 | **[+0.112, +0.228] ★** |
| 7B | 0.8690 | 0.8536 (α=0.6) | **0.8971** | 0.8993 | **[+0.022, +0.066] ★** |

**두 스케일 모두 우리가 유의하게 우위.** 주목: FOCUS 정식은 **기준선보다도 낮다**(3B 0.583 < 0.697).

### 이 비교의 한계 — 반드시 함께 보고할 것
1. **노이즈 강도가 다르다.** 우리 로그는 순수 노이즈(λ=1)이고 FOCUS는 λ를 튜닝한 혼합이다.
   λ를 낮추면 FOCUS가 나아질 수 있다. **이 재구성은 FOCUS에 불리한 λ를 쓴 것이다.**
2. **이미지 4장 조건은 재구성 불가.** FOCUS는 "i만 깨끗+나머지 전부 노이즈"가 필요한데
   우리 로그는 "i만 노이즈"뿐이다. 2장에서만 두 정의가 일치한다.
3. 공식 코드(github.com/yejipark-m/FOCUS)를 돌린 것이 아니다.

→ **논문 주장으로 쓰려면 공식 코드 + λ 튜닝으로 다시 재야 한다.** 지금은 예비 근거.

## 3. 관련도는 이산이 아니라 연속이다 — 그리고 그것이 우리 실패 지점이다

문항별 |Δmargin|을 최댓값=1로 정규화한 분포 (사진 4장, n=300):

| | 2위의 상대 크기 (중앙값) | 2위가 1위의 절반 이상인 문항 | 1위−2위 격차 < 0.2 |
|---|---|---|---|
| 3B | 0.304 | **33%** | 13% |
| 7B | 0.140 | 12% | 4% |

**3B는 3문항 중 1문항에서 두 번째 이미지도 1위의 절반 이상 영향을 준다.** 이산 판별이
정보를 버리고 있다.

### 그리고 그 지점에서 판별이 정확히 무너진다

1위−2위 격차로 3분위 나눈 판별 정확도:

| | 격차 하위 25%(애매) | 중간 50% | 상위 25%(명확) |
|---|---|---|---|
| 3B | **0.493** (우연 수준) | 0.733 | 0.960 |
| 7B | 0.760 | 0.993 | 1.000 |

**3B의 전체 판별 정확도 0.730은 "명확한 문항 0.96 + 애매한 문항 0.49"의 평균이다.**

## 4. 이것이 abstention 실패(docs/38 P3)와 모순되지 않는 이유

격차 신호는 **오판을 정확히 예측한다**(위 표). 실패한 것은 그 신호에 대한 **대응**이었다 —
"확신 없으면 아무것도 안 함(기권)"은 잘못된 대응이다. 기준선 자체가 나쁘기 때문이다.

**올바른 대응은 부분 개입이다**: 격차가 작으면 두 이미지를 모두 남기거나, 상대 크기에 비례해
차단 강도를 조절한다. 이건 **미측정**이며 다음 실험 1순위다.

이미 있는 근거: 소프트 마스킹 λ 스윕(docs/24)은 **전 문항 일괄 적용**에서 하드 차단이 최적이었다.
문항별 적응(격차가 작을 때만 소프트)은 시도한 적이 없다.

## 5. 다음 실험 (GPU 필요, 각 ~1시간)

- **E1 적응형 top-k**: 격차 < τ이면 상위 2개 유지, 아니면 1개. τ를 스윕.
- **E2 비례 차단**: 이미지 i의 차단 강도 λ_i = f(1 − 상대 |Δmargin|_i). 연속 관련도를 그대로 반영.
- **E3 FOCUS 공식 코드** + λ·α 튜닝으로 정식 비교 (논문 주장에 필수)
