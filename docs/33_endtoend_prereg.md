# 오라클 없는 종단 성능 — 사전 등록

작성 2026-08-23, **측정 전**. 실행 `scripts/35_endtoend.py` (`pbs/sd_e2e_n1.pbs`).

## 왜

지금까지의 모든 헤드라인 수치(0.90~0.97)는 어느 이미지가 방해인지 **알려준** 오라클 조건이다.
실현 수치는 근사(낙관 상한)뿐이었다(docs/23). 리뷰어가 처음 보는 표는 이것이어야 한다:
무개입 M / 실현(컨트롤러 포함) / 오라클 — 나란히.

## 방법

- 문항: scale_auc_items (기존과 동일, n=300, N∈{1,2,3})
- 컨트롤러 선택: **기존 loo{TAG}.jsonl의 저장 margin으로 재현** (사전 고정 규칙
  pick = argmax_i |margin(B_i) − margin(M)| — docs/23과 동일, 변경 없음)
- 새 조건 4: ORD_READ / REAL_READ / ORD_KEEP / REAL_KEEP
  (ORD=진짜 관련만 남김, REAL=컨트롤러 선택만 남김; READ=나머지 읽기만 차단, KEEP=전면 차단)

## 판정 (주 종점: 3B, N=3)

| | 조건 | 해석 |
|---|---|---|
| **통과** | AUC(REAL_READ) − AUC(M) 의 95% CI 하한 > 0 | 오라클 없이 작동하는 방법 |
| **부분** | 통과 실패이나 REAL_READ ≥ M (CI 0 포함) | 해는 없으나 이득 미확정 — 컨트롤러 개선 필요 |
| **실패** | REAL_READ < M 유의 | **방법이 아니라 진단 도구로 보고** |

부 종점(탐색): ① REAL_READ vs REAL_KEEP — 경로 선택성이 실현 조건에서도 이득인가
② 오판 문항만의 AUC — 실패 꼬리 정량화 ③ 7B 동일 표.

## 해석 제약

- 이 표가 나오기 전까지 어떤 자료에도 "방법 성능"으로 오라클 수치를 쓰지 않는다.
- 컨트롤러 규칙을 결과를 보고 바꾸지 않는다. 개선 시도는 별도 사전등록.
