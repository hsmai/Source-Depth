# 미팅 슬라이드 키트 v2 — PPT 제작용 (2026-08-12 미팅)

> **v1과의 차이**: 외부 novelty 검토(docs/09) 반영 + 오늘 밤 신규 실험(gate1) 결과 반영.
> 스토리가 "원안 GO"에서 **"현상·메커니즘·컨트롤러 신호까지 실측 확보 → 남은 3개 관문을 단기 검증"**으로 바뀜.
>
> **읽는 법**: `[헤드라인]` = 슬라이드 최상단 한 문장(제목이 곧 주장) · `[시각]` = 그릴 것의 정확한 스펙
> · `[텍스트]` = 복붙용 최소 불릿 · `[멘트]` = 말로 채울 것 (슬라이드에 넣지 말 것)
> **원칙**: 슬라이드당 불릿 ≤4, 숫자는 크게, 시각자료가 주인공. `[EXT]` = 내일 아침 결과로 채울 슬롯.
>
> **모든 수치는 실측이며 `results/`에 raw 보존.** 사전 등록(pre-registered) 항목과 탐색적(exploratory)
> 항목을 슬라이드에서 반드시 구분 표기 — 이것이 신뢰의 핵심.

## Slide 2 — 문제: 멀티이미지에서 출처가 섞인다 [배경]

**[헤드라인]** 여러 이미지가 들어가면 모델이 "어느 이미지에서 온 정보인지"를 혼동한다

**[시각]** 제안서 3페이지 그림 재사용 (파란 모자/빨간 모자 → 모델이 2번 이미지 정보로 오답).
오른쪽에 우리 실측 숫자를 배지로: **단일 이미지 89.3% → 이미지 2장 72.0%** (동일 문항, 셀 1)

**[텍스트]**
- 선행 연구가 이미 명명한 실패 모드: cross-image leakage (FOCUS'25), multi-view hallucination (MVH-Bench'26)
- 기존 해법은 전부 **full depth 전제** + 계산을 **더** 씀 (FOCUS: N+1 forward)

**[멘트]** 문제 자체는 새롭지 않다는 걸 먼저 인정하고 들어간다 — 우리 기여는 "어디서 생기는가"와 "계산을 줄이며 고친다"에 있음.

## Slide 3 — 가설: depth가 곧 이미지 간 혼합 통로 [아이디어]

**[헤드라인]** 서로 다른 이미지가 섞이는 통로는 layer마다 한 번씩 일어나는 self-attention뿐이다

**[시각]** 제안서 4페이지 그림(얕은 실행 vs 깊은 실행) 재사용. 아래에 개입 방식 도식 1줄:
```
layer L 이후 distractor의 KV 열을 attention에서 제외
  = softmax 분모에서 제외 = 그 KV가 "없는 것"과 수학적으로 동일
  → 근사 억제가 아니라 구조적 차단 (단, L 이전에 이미 전파된 정보는 남음)
```

**[텍스트]**
- 실행 layer 수 = 이미지 간 정보가 섞일 수 있었던 **횟수**
- 예측: 무관 이미지를 후반에서 끊으면 (a) 오답 회복 (b) 계산 절감이 **동시에** 일어난다

**[멘트]** 괄호 안 단서를 반드시 말할 것 — 정직성이 신뢰를 만든다. "L 이전 전파는 못 막습니다. 그 잔여 효과가 얼마인지도 수치로 쟀습니다(19%)."

## Slide 4 — 실험 설계: 왜 이렇게 짰는가 [요청 2·타당성]

**[헤드라인]** 반증 가능하도록 설계했다 — 대조군, 양방향, 그리고 역방향 컨트롤

**[시각 1]** 4셀 2×2 표 (색으로 leak 측정 셀 vs 대조군 구분):
```
              distractor에 질의 객체 O    X
정답 No   |  셀1  주 leak (No→Yes)  |  셀3  대조군
정답 Yes  |  셀4  대조군            |  셀2  역방향 leak (Yes→No)
```
**[시각 2]** 조건 축 막대 도식: `S(단독)` `M(2장, baseline)` `T(L) L=4..24` `T(0) 완전차단` `T-rel(8) 역방향 컨트롤`
**[시각 3]** 설계 타당성 3개 아이콘+한 줄:
- 🔁 **양방향**: 셀1(No→Yes)과 셀2(Yes→No)는 반대 방향 → 단일 편향으로 설명 불가
- 🎯 **oracle**: 관련 이미지를 알고 시작 → 가설 검증과 컨트롤러 성능을 **분리**
- ⚠️ **역방향 컨트롤**: 관련 이미지를 대신 끊으면 무너져야 정상

**[텍스트]**
- POPE(COCO) adversarial 600문항 = 4셀 × 150, distractor는 COCO annotation으로 조건 검증
- **판정 기준을 실험 전에 문서로 동결**하고 결과를 보고 바꾸지 않음 (pre-registered)

**[멘트]** "왜 이 세팅이 타당한가"의 답 = 결과가 틀렸을 때 틀렸다고 나올 수 있게 만들었기 때문.

**[헤드라인]** 파이프라인 정합성 3종을 먼저 통과시킨 뒤에야 본 실험에 들어갔다

**[시각]** 체크 배지 3개 + 규모 정보 한 줄:

✅ 차단이 실제로 작동      ✅ 평가가 정상          ✅ 마스킹 ≡ 실제 제거

**[멘트]** 이 슬라이드가 있어야 뒤의 모든 숫자가 산다. 특히 "마스킹 ≡ 실제 제거"는 오늘 밤 실제 구현으로 검증한 것.

## Slide 6 — 결과 ①②: 문제는 실재하고, 차단하면 회복된다 [요청 4]

**[헤드라인]** distractor가 21%의 답을 뒤집고, layer 4 이후 차단만으로 그 81%가 회복된다

**[시각 1]** Flip Rate 막대 4개 (셀1 21.3 / 셀3 0.0 / 셀2 12.7 / 셀4 4.7 — leak 셀은 진한 색, 대조군은 회색)
**[시각 2]** **fig1_accuracy_vs_L.png** (셀1·2 패널) — 콜아웃 3개:
`T(0) 상한 0.933` / `M baseline 0.720` / `T4 = 0.920 — 단일이미지(0.893)보다도 높음`

**[텍스트]**
- 회복 81.0% vs 부수 피해 3.7% (셀1) — 회복이 피해를 **22배** 상회, McNemar p = 6×10⁻⁷
- 이론 prefill 연산 절감 42.4% (distractor 토큰이 36층 중 32층을 건너뜀)
- ⚠️ 정직 고지: 셀2(역방향)는 확신도 높은 문항만 남기면 사라짐 → **주 증거는 셀1 + 인과 실험**

**[멘트]** 마지막 불릿을 스스로 말하는 게 중요. "저희가 margin 민감도까지 봤고, 약한 축은 약하다고 보고합니다."

**[헤드라인]** 질문 유형이 바뀌면 최적 depth가 정반대가 된다 — 고정 정책은 원리적으로 불가능하다

**[시각]** **fig3_opposite_depth_policies.png** — 이 발표의 대표 그림. 크게 배치.
콜아웃 3개:
- 파란 곡선(unary + distractor): L=4에서 **+21%p** (차단이 이득)
- 빨간 곡선(relational "둘 다에 있나?"): L=4에서 **−51%p** (차단이 손해)

**[텍스트]**
- 같은 모델·같은 개입인데 **72%p 격차** → 하나의 고정 depth로 양쪽 최적화 불가
- 신규 관찰: **관계 추론이 켜지는 층(20–24)이 곧 출처 오염이 생기는 층** — depth의 양날을 실측
- (탐색적 실험 — 사전 등록 아님, 300문항)

**[멘트]** "이게 오늘 가장 중요한 결과입니다. 제안서에서 가설로만 그렸던 'Type A / Type B'가 실제 데이터에서 X자로 교차합니다. 그리고 두 효과가 같은 층 구간에서 켜진다는 건 예상 못 했던 발견입니다 — 관계 추론과 출처 혼동이 같은 계산의 양면이라는 뜻입니다."

## Slide 9 — ★ 컨트롤러: 실패로 보였던 것이 feature 문제였다 [요청 4]

**[헤드라인]** 사전 기준 72.5%로 미달했던 신호가, head 하나만 골라 보니 layer 8에서 99.8%였다

**[시각 1]** **fig4_controller_feature_sweep.png** — layer별·feature별 식별률 곡선 (80% 기준선, layer ≤14 구간 음영)
**[시각 2]** 비교 배지 2개:
```
Phase 0 (사전 등록)         오늘 (탐색적)
16개 head 평균              단일 head 선택 (2-fold 교차검증)
layer 8 → 72.5% ❌          layer 8 → 99.8% ✅   layer 5 → 98.3%
```

**[텍스트]**
- 선택된 head가 두 fold에서 **완전히 동일** → 우연한 과적합이 아님
- 의미: 관련 이미지 식별을 위해 깊이 갈 필요가 없다 = 차단 시점을 앞당길 수 있다
- ⚠️ **미해결**: 관련 이미지가 항상 첫 번째 위치 → "첫 이미지 head"와 구분 안 됨 `[EXT: 순서 뒤집기 검증 중]`

**[멘트]** 마지막 불릿이 핵심. "이 숫자를 그대로 믿으면 안 됩니다. 지금 순서를 뒤집은 대조 실험이 돌고 있고, 그 결과가 나와야 확정입니다." — 이 태도가 top-tier 리뷰를 통과하는 태도.

## Slide 10 — 실측 속도: 이론과 현실의 격차를 먼저 쟀다 [요청 4·정직성]

**[헤드라인]** 이론 절감 42.4% 대비 실측 TTFT 절감은 9.7% — 격차의 원인까지 규명했다

**[시각]** 3단 막대: `이론 FLOPs 42.4%` → `실측 TTFT 9.7%` + 격차 원인 3개 아이콘:
```
① vision encoder는 여전히 두 이미지를 모두 인코딩 (LLM 밖의 고정 비용)
② per-layer Python 슬라이싱 오버헤드 (커널 수준 구현 시 해소)
③ 짧은 시퀀스에서는 attention이 memory-bound
```
옆에 검증 배지: `마스킹 대비 예측 일치율 100% → 정확도 수치는 실제 구현에도 그대로 전이`

**[텍스트]**
- 마스킹이 아니라 **실제로 토큰을 시퀀스에서 제거**하는 구현으로 측정 (40문항)
- Phase 1 과제: ViT 단계 배분 + 커널 수준 구현

**[멘트]** "이 숫자를 굳이 보여드리는 이유는, 이론치만 들고 가면 리뷰에서 반드시 깨지기 때문입니다. 먼저 재고 먼저 인정하는 게 낫습니다."

## Slide 11 — 선행 연구 지형: 어디가 비어 있는가 [요청 5·필수]

**[헤드라인]** 인접 연구 12편을 전수 확인했다 — 비어 있는 칸은 "이미지별 실행 깊이 × 출처 정확도"다

**[시각]** 2축 매트릭스 (가로: 배분 단위 = 전역 / 토큰 / **이미지** · 세로: 목표 = 효율 / **정확도(출처)**).
각 칸에 논문 배치, 우리 자리는 빈 칸에 별표:
```
              전역 균일        토큰 단위        이미지 단위
효율만    |  VTW(AAAI'25)  |  FastV 계열    |  MVPruner(ECCV'26)  |
          |  ShortV(ICCV'25)|               |  (토큰 수 예산)      |
정확도    |  RSCD, FOCUS   |  PruneHal      |   ★ 여기 (Ours)     |
(출처)    |  Delimiter(ICLR'26)|            |   실행 depth 예산    |
```

**[텍스트]**
- MVPruner(ECCV'26)가 가장 근접 — 단, **토큰 수** 예산이며 모든 view가 전 layer 통과, 환각 목표 없음
- RSCD는 layer 범위 개입을 하지만 **text-to-text** attention이고 계산이 오히려 +10%
- 폐기한 주장: "depth 절감 최초", "leakage depth 분석 최초" → **정직하게 좁힌 주장**으로 교체

**[멘트]** 이 슬라이드가 있으면 교수님이 "그거 이미 있지 않나?"를 물을 필요가 없어진다. 먼저 답을 준비해 간 것.

## Slide 12 — 종합 판정과 남은 관문 [요청 5]

**[헤드라인]** 문제·메커니즘·인과·신호는 확보했다 — 남은 것은 "적응이 정말 필요한가"와 "실제로 빨라지는가"

**[시각]** 2열 대비 표 (초록 = 확보 / 주황 = 미확보):
```
✅ 확보한 것 (정량)                          ⏳ 아직 못 한 것
문제 실재      flip 21.3% vs 대조군 0%       중간 depth 최적점의 존재  [EXT 오늘밤]
메커니즘       회복 81%, p=6e-7              비-oracle 컨트롤러 완결   (2~4주)
인과           0.79→0.50, p=4e-38            실측 속도 우위            (2~4주)
정책 비가역성  +21%p vs −51%p (72%p 격차)    다른 모델·벤치 일반화     [EXT 오늘밤 7B]
컨트롤러 신호  layer 8 단일 head 99.8%
```

**[텍스트]**
- 제안서의 go/no-go 기준(**Type-B 구간의 존재**)은 fig3으로 충족 → **원안 진행 조건 성립**
- 단, 위 4개를 **kill gate**로 걸고 2~4주 내 판정 — 하나라도 명확히 실패하면 축소 또는 방향 전환

**[멘트]** "6개월을 먼저 걸지 않고, 성립 조건을 먼저 깨보겠습니다"가 이 슬라이드의 메시지.

## Slide 13 — 유력 후보 방법론 (실측 근거 기반) [요청: 후보 제안]

**[헤드라인]** 데이터가 가리키는 설계는 "얕게 판정하고, 이미지마다 다른 깊이로 끊는다"

**[시각]** 후보 3개 카드 (각 카드에 실측 근거 수치를 크게):
```
┌─ A. Early-decide, per-image exit  ★유력 ────────────────┐
│ layer 5~8에서 head 신호로 관련 이미지 판정               │
│ → distractor는 그 지점부터 차단, 관련 이미지는 유지       │
│ 근거: 신호 99.8%@L8 · 차단 회복 81%@L4 · 절감 42%(이론)   │
└──────────────────────────────────────────────────────┘
┌─ B. Question-type routing ────────────────────────────┐
│ unary/relational을 먼저 분류해 depth 정책을 전환          │
│ 근거: 같은 L에서 +21%p vs −51%p — 정책 분기의 이득이 큼   │
└──────────────────────────────────────────────────────┘
┌─ C. Risk-calibrated α-knob  (차별화 포인트) ────────────┐
│ "출처 오류율 ≤ α 유지하며 계산 최소화"의 제약 최적화        │
│ 기존 pruning은 전부 휴리스틱 threshold → 보증이 없음      │
│ [EXT: 오늘밤 Pareto 곡선 산출 중]                        │
└──────────────────────────────────────────────────────┘
```

**[텍스트]**
- A는 신호(L8)와 개입점(L4~16)이 **같은 구간**에 있어 실현 가능 — 오늘 실측이 뒷받침
- C가 MVPruner류 휴리스틱 배분과 갈라지는 지점 (제안서 기여 4의 구체화)

**[멘트]** "후보를 하나로 정하지 않고 3개를 병렬로 검증하는 이유는, A가 실패해도 B·C가 살아있게 하기 위해서입니다."
