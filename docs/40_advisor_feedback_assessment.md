## 2. 기존 로그 재분석 (문항 단위)

### 2.1 방해 사진 때문에 "맞던 문항이 틀리게 된" 비율

위치 벤치(질문이 "첫 번째 사진"을 지목), 적대 셀 300문항:

| | 방해 1장 | 2장 | 3장 | 우리 방법 적용 시 정확도 변화 (1/2/3장) |
|---|---|---|---|---|
| 3B | 18.7% | 27.7% | 36.0% | +3.7 / +14.3 / +22.0 %p |
| 7B | 3.7% | 5.0% | 5.7% | **−3.7 / −3.0 / −0.7 %p** |

7B의 반대 방향(방해가 있어서 오히려 맞게 된 문항)은 2.3/2.0/2.7% → 순피해 1.4~3.0%p.
**7B에서 실현 방법은 고정 임계값(=실제 디코딩) 정확도를 낮춘다.** 08-26에는 7B를 AUC로만 보고했다.

균형 표본(4셀 600문항, 사진 2장) — 적대 셀만이 아닌 전체:

| | 피해 | 이득 | 순 | McNemar p |
|---|---|---|---|---|
| 3B | 9.7% (58) | 4.7% (28) | +5.0%p | 0.0016 |
| 7B | 4.8% (29) | 1.5% (9) | +3.3%p | 0.0017 |

셀별(사진 2장, 관련 사진이 앞):

| 셀 | 3B 피해 | 7B 피해 |
|---|---|---|
| 1 적대 (정답 no · 방해에 객체 있음) = "객체 누출" | 21.3% | **0.7%** |
| 2 적대 (정답 yes · 방해에 객체 없음) | 12.7% | 8.7% |
| 3 대조 (정답 no · 방해에도 없음) | 0.0% | 0.7% |
| 4 대조 (정답 yes · 방해에도 있음) | 4.7% | 9.3% |

- 7B는 "방해 사진의 물체를 그대로 답하는" 누출이 사실상 없다(0.7%). 7B의 피해는 방해 내용과 무관하게
  정답 yes 문항에서 나온다(8.7%, 9.3%) — 내용 무관 yes→no 이동.
- 3B도 관련 사진을 뒤에 두면 셀1 피해가 21.3% → 11.3%로 줄고 셀4가 4.7% → 14.7%로 는다
  (posbal_results). "객체 누출"이라는 틀은 3B에서도 관련 사진이 앞일 때만 깨끗하다.

### 2.2 '예' 응답 비율 이동과 판별력의 분리 (사진 4장 위치 벤치 / 3장 anchor)

| | 조건 | 정확도 | 예 비율 | 최적 임계 정확도 | AUC |
|---|---|---|---|---|---|
| 7B 위치 | 사진 1장 | 0.787 | 0.340 | 0.850 | 0.903 |
| | 무개입 | 0.757 | 0.297 | 0.817 | 0.874 |
| | 우리(실현) | 0.750 | 0.270 | 0.837 | 0.892 |
| | 오라클 | 0.750 | 0.270 | 0.833 | 0.896 |
| 7B anchor | 무개입 | 0.627 | 0.160 | 0.703 | 0.729 |
| | 우리(실현) | 0.730 | 0.243 | 0.797 | 0.839 |
| | 오라클 | 0.737 | 0.243 | 0.883 | 0.948 |

정답 yes가 50%인데 7B의 예 비율은 0.16~0.34다. 7B 수치는 보정(calibration)에 크게 좌우되므로
**상수 오프셋 재보정을 모든 비교의 baseline으로 넣어야 한다** (지금까지 넣은 적 없음).

### 2.3 anchor 벤치에서 실현 이득의 출처

| | selector 정확도 (정답 no 셀) | 총 순이득 | 그중 selector가 **틀린** 문항에서 나온 것 |
|---|---|---|---|
| 3B 사진 2장 | 0.557 (0.160) | +85문항 | +62 (73%) |
| 3B 사진 3장 | 0.763 (0.600) | +102 | +15 |
| 7B 사진 2장 | 0.733 (0.520) | +18 | +2 |
| 7B 사진 3장 | 0.650 (0.447) | +31 | +2 |

3B·2장에서는 selector가 정답 no 셀의 84%에서 **방해 사진을 관련 사진으로 고른다**(그 사진을 빼면 답이 가장 크게
흔들리므로). 그 뒤 진짜 관련 사진의 읽기를 막으면 모델이 "no"라고 답해 우연히 맞는다. **2셀 구성의 산물**이다.

### 2.4 "읽기만 차단" 대 "열 전체 차단" — 두 방식이 구조적으로 달라지는 구간만

CLIP이 관련 사진을 맞게 골랐고 그 사진이 맨 앞이 아닌 문항 (anchor 벤치):

| | n | 정확도 읽기차단 / 전체차단 | AUC | 읽기차단만 정답 / 전체차단만 정답 |
|---|---|---|---|---|
| 3B 2장 | 125 | 0.808 / 0.856 | 0.968 / 0.969 | 0 / 6 |
| 3B 3장 | 146 | 0.849 / 0.890 | 0.960 / 0.960 | 1 / 7 |
| 7B 2장 | 125 | 0.736 / 0.712 | 0.917 / 0.937 | 5 / 2 |
| 7B 3장 | 146 | 0.719 / 0.740 | 0.945 / 0.952 | 4 / 7 |

관련 사진이 맨 앞이면 두 방식의 margin이 전부 동일(120/120, 74/74). 08-25에 "주 종점 통과"로 적은
3장 전체 AUC 우위(0.763 대 0.742)는 **selector가 틀린 80문항에서 덜 확신하며 틀린 데서** 나온다(AUC 0.114 대 0.082).
**selector가 맞을 때 읽기 차단이 전체 차단보다 낫다는 근거는 로그에 없다.**
(주의: 로그의 "전체 차단"은 열 전체 마스킹이며 이미지를 실제로 빼고 다시 인코딩한 것은 아니다.)

### 2.5 "이미지끼리 차단하면 무너진다"는 서수 지시 질문에서만 관찰됨

| 질문 유형 | 설정 | 이미지 간 차단 − 무개입 (AUC) |
|---|---|---|
| 서수 지시 ("첫/두 번째 사진") | 원래·뒤집은 배치 × 3B·7B | −0.29, −0.42, −0.23, −0.43 |
| 서수 지시 | MIMIC식 12~23층 × 3B·7B | −0.29, −0.02 |
| 서수 없음 ("이 사진들 중/전부") | any-of-3 × 3B·7B | +0.001, −0.002 |
| 서수 없음 | all-of-3 × 3B·7B | −0.025, −0.055 |

- 큰 붕괴는 서수 지시 설정에서만 나오고, 그때 AUC가 0.40~0.45로 **0.5 아래로 뒤집힌다.**
- 마스크 설정이 `MASK_SPAN_MODE = with_delimiters`라 상대 이미지의 경계 토큰까지 끊는다.
- 따라서 "섞임이 보호적"이라기보다 **"자기가 몇 번째 사진인지에 대한 정보가 끊겼다"**로 설명될 수 있다(가설).
  내용 지시 질문(anchor/VHs)에서 이미지 간 차단만 따로 잰 적은 없다.

### 2.6 (참고·상관 수준) 마지막 토큰의 attention

후반 25% 층에서 이미지에 준 주의 중 방해 사진 몫: 3B 0.398, 7B 0.305. 7B가 방해 사진을 덜 읽는 방향이나,
마지막 토큰 한 행·위치 교란·상관 증거라 주장으로 쓸 수 없다.

## 4. 피드백별 답

### F1. 3B에서는 뚜렷하지만 7B에서는 거의 없다 — 풀 가치가 있는가

- **인정**: 실험한 구간(사진 ≤4장, 존재 질문, 관련 사진을 지목)에서 7B 순피해는 1.4~3.0%p이고 누출은 0.7%다.
- **문헌**: 관련 사진을 지목하거나 앞에 두면 7B급은 강건하다는 보고가 있다(Visual-RAG, MIMIC, 14모델 연구에서 Qwen2-VL 0.00).
  반면 **모델이 스스로 관련 사진을 찾아야 하는** VHs에서는 장수가 늘수록 큰 모델도 떨어진다:
  Qwen2-VL-7B 80.9→76.6(2장)→73.6(3장)→67.9(5장)→62.6(10장), GPT-4o 82.5→73.3(5장)→68.2(10장)→55.3(100장),
  Qwen3VL-8B 87.8→82.0→77.9→74.7→69.2(10장), Qwen2.5-VL-32B 83.8→79.1(5장)→74.7(10장, 100문항 변형판).
- **그러나** 그 하락은 (a) 남이 이미 보인 것이고, (b) 저자들은 누출이 아니라 **관련 사진 탐색 실패·위치 편향**으로 귀인하며,
  (c) 해법(MIRAGE, ReToken, LoRA SFT)도 이미 나와 있다.
- **모르는 것**: 우리 파이프라인에서 Qwen2.5-VL-7B가 VHs N=5~10에서 얼마나 떨어지는지, 그중 몇 %가 길이·위치가 아닌 내용 탓인지.

### F2. 기존 환각 방법으로 이미 풀리는 것 아닌가

- **인정**: 답할 자료가 없다. 공식 코드 baseline 0건, 프롬프트 baseline 0건, 사진 번호 라벨("Picture 1:") 0건, 재보정 0건.
- **문헌**: 단일 이미지 환각 기법을 멀티이미지에 옮긴 결과는 약하고 모델 의존적이다
  (FOCUS 표: VCD식이 Qwen2.5-VL에서 +0.37/+0.76; RSCD: 잡음 범위 안). **"실패가 입증됐다"고는 말할 수 없다.**
- **구조적 딜레마**: 관련 사진이 정확히 1장이면 "사진마다 따로 묻기"나 "검색 후 제거"가 자연스러운 해법이고,
  읽기 차단이 그보다 낫다는 근거는 없다(§2.4). 관련 사진이 여러 장이면 막을 사진이 없다.
- **다음 질문 예상**: "왜 학습 없이 해야 하나" — LoRA SFT가 7B를 5장에서 68.45→92.92로 올린다(LAid). 답이 준비돼 있지 않다.

### F3. 실제로 문제가 나타나는 표본 비율은 얼마인가

- **우리 데이터**: 균형 표본에서 3B 9.7%(순 5.0%p), 7B 4.8%(순 3.3%p). 적대 셀만 보면 3B 17.0%, 7B 4.7%.
  "20%p 이상"은 적대 셀 한정 수치였다. 7B는 교수님이 예로 드신 "100개 중 2~3개" 수준이 맞다.
- **표준 멀티이미지 벤치**(MuirBench, MIRB, Mantis-Eval, BLINK, MMIU, MIHBench): 설계상 모든 이미지가 필요하다.
  대상 문제의 비율은 구성상 0에 가깝다(과제 정의를 읽고 내린 추론이며 문항 수를 세지는 않았다).
- **방해 이미지가 구성상 있는 벤치**: VHs, MRAG-Bench, MMLongBench-Doc 단일 증거 페이지 부분집합 등.
  여기서 방해 때문에 틀리는 비율은 재야 한다.
- **재야 할 수치(F3의 문자 그대로의 답)**: 가장 좋은 자명 baseline이 틀리고 오라클 개입이 맞히는 문항 비율 − 그 반대.

## 6. 제안 — 판정 실험 패키지 (초안, 합의 전)

원칙: 방법 개발 중단. Qwen2.5-VL-3B/7B만. 공개 VHs 1,000문항을 test로, 기존 anchor 600문항은 dev(프롬프트 선택)로.
싼 것부터. 3~4주, 약 60~70 GPU시간. **회색 지대는 연장이 아니라 불통과.**

### 0단계 (GPU 0)
- 서버 비밀번호 변경 · VHs와 COCO 2017 필요 이미지 내려받기 · OpenReview 2편과 ReToken 부록 정독
- VHs N=2/3/5의 4셀 정확 문항 수 (COCO 2017 주석 결합) — 공개 벤치에서 "누출 셀" 비율
- 이 문서의 문턱값을 교수님과 합의 후 고정

### 1단계
| | 실험 | 답하는 질문 |
|---|---|---|
| E1 | VHs single-needle N=1,2,3,5,10 (N=20은 300문항). 문항 단위 피해율 H(N). 대조: 회색 빈 이미지 패딩(길이·위치), target 있는/없는 방해(내용·누출), 순서 재섞기(잡음 바닥), 사진 번호 라벨. 먼저 출판 수치 하나를 재현 | F1, F3 |
| E2 | 오라클 읽기 차단 대 진짜 단독 입력(N=1) 대 전체 차단. 관련 사진이 맨 앞이 아닌 문항만 집계 | F2(개입의 존재 이유) |
| E3 | 자명 baseline: 사진 번호 라벨, 무시 프롬프트, 질문 앞배치·반복, 2단계 자기 선택, SigLIP2/CLIP 후 제거, 사진마다 따로 묻기, 상수 오프셋 재보정 | F2 |
| E4 | 이미지 간 차단: 서수 지시 대 내용 지시 × 경계 토큰 포함/패치 전용 | 정정 3의 확정 |

### 중단 기준 (7B, N∈{5,10} 풀링, 문항 단위 재표집)
- **K0**: 공개 데이터에서 3B의 N=3 하락 < 8점 → 3B 효과도 우리 구성의 산물. 전체 중단.
- **K1**: (실제 방해 − 회색 패딩) 하락 < 3점 → 7B 이상에 대한 주장 폐기.
- **K2**: 오라클 읽기 차단 − 무개입 < 4점 → 고칠 대상 없음.
- **K3**: 2패스 이하 자명 baseline이 오라클과 2점 이내 → 방법 라인 영구 종료.
- **K4**: 관련 사진 비선두 문항에서 읽기차단 − 제거의 95% CI 상한 < +1점 → "지우지 않고 읽기만 막는다" 주장 종료.

### 2단계 (어떤 중단 기준도 발동하지 않을 때만)
타 계열 7~8B, 32B 행동 측정 1점(A100 또는 API), FOCUS·DAB·DelimScaling 공식 코드, MRAG-Bench 자연 유병률, activation patching.

## 7. 판정 후 갈림길

- **K3 또는 K4 발동(가장 가능성 높음)**: (가) "이미지 간 attention은 언제 이롭고 언제 해로운가 — 서수/내용 지시 × 장수"로
  문헌의 부호 충돌(ReToken·DelimScaling 대 BlindSight·Perturbed K/V)을 설명하는 짧은 진단 논문(워크숍·Findings·TMLR), 또는 (나) 내부 노트로 닫고 다른 주제로 이동.
- **K0 또는 K1·K2 발동**: 닫는다.
- **아무것도 발동 안 함**: ICCV 2027(3월 초 추정, 미공식) 또는 ACL 2027(ARR 01-04, 리뷰 기여자 필요)을 목표로 2단계.

주관적 전망(측정 아님): 톱티어 본 학회 10% 이하, Findings·워크숍·TMLR급 35~40%, 판정 후 종료 약 50%.

## 8. 실험으로 되돌릴 수 없는 것

- 벤치·개입·기전 절반의 우선권 (VHs, MIBench, ReToken/AIF, ICLR 2027 투고들).
- 7B·사진 ≤4장 구간에서 효과가 작고 방법이 정확도를 낮춘다는 측정 사실.
- 표준 멀티이미지 벤치에는 무관 이미지가 없어 이 방법이 점수를 올릴 수 없다는 구조.
- N+1 패스 selector의 비용(문제가 커지는 N≥20에서 가장 비쌈)과, 관련 사진 1장 과제에서는 제거가 자연스러운 해법이라는 딜레마.
- 첫 토큰 예/아니오 평가로는 생성 중 개입하는 방법(OPERA 등)과 공정 비교 불가.
- 현 자원으로 72B·N≥50 마스크 실험 불가.
