# FOCUS와 무엇이 다른가 — 그리고 무엇을 측정해야 하는가

2026-08-14. 우려: "N+1 forward + 마스킹 + 결합"이라는 레시피가 FOCUS(2508.13744)와 같다.
**타당한 우려이며, 그대로 두면 '픽셀 노이즈를 attention mask로 바꾼 FOCUS'로 읽힌다.**

## FOCUS 요약

타깃 1장만 남기고 나머지 이미지를 **픽셀 단위 random noise**로 덮음 → 이미지 수만큼 반복해
logit 수집 → 집계 → noise-only reference로 contrastive 보정. training-free, N+1 forward,
Qwen2.5-VL 3B/7B 포함, 개선폭 최대 +3.22%p, layer 분석 없음.

## 구조적 차이 3가지 (전부 우리 측정으로 뒷받침됨)

### ① 우리 최적 처방을 FOCUS는 구현할 수 없다

우리 실측: **읽기 경로만 차단(0.9078) > 이미지 통째 제거(0.8894)**,
CI [+0.007, +0.031], 회복률 121% (뒤집은 배치, 3B).

FOCUS는 픽셀을 덮으므로 이미지가 **모든 것으로부터** 사라진다 — 다른 이미지에게도.
그런데 이미지 간 흐름은 **보호 요인**이다 (끊으면 −0.23 ~ −0.43).
**FOCUS는 유익한 부분까지 함께 버린다.** 취향 차이가 아니라 측정된 손해다.

개입 단위 자체가 다르다: FOCUS = 이미지 통째 / 우리 = **(질의 행 × 키 열) 사각형**.

### ② FOCUS는 매 pass마다 vision encoder를 다시 돌린다

픽셀을 바꾸면 인코딩을 새로 해야 한다. 우리는 같은 시각 인코딩을 재사용하고 KV 가시성만 바꾼다.

```
FOCUS :  (N+1) × (vision encoder + LLM 전체)
우리  :  1 × vision encoder  +  (N+1) × LLM 일부
```

### ③ "일부"가 어디인지 우리는 안다 — FOCUS는 층 분석을 하지 않았다

분석이 방법을 싸게 만드는 지점. 제안 파이프라인:

```
1회  전체 forward, KV 캐시
N회  L층부터만 재계산 (이미지 i의 KV 마스킹) → Δ_i = |margin_i − margin_all|
     관련 이미지 = argmax Δ_i        (위치 무참조 → 위치 편향 구조적 불가)
1회  L층부터만 재계산 (질문 → 무관이미지 읽기만 차단)
```

L은 인과 개입으로 특정했다: 이미지 간 통합은 앞쪽 ~16층에서 끝난다
(ISO0 −0.055 유의 vs ISO16 −0.005). 읽기 쪽 L은 `99675`(scripts/29_read_depth.py)가 측정 중.

L=16/36이면 반사실 하나당 약 **55%** 비용. vision encoder 재사용분까지 더하면 절감은 더 크다.

## 반드시 측정해야 할 것 — 아직 안 한 것

**주장만으로는 부족하다. 다음 두 숫자가 없으면 위 논리는 종이 위 계산이다.**

1. **층 절단 반사실이 실제로 작동하는가.**
   L층부터 마스킹한 반사실로도 컨트롤러 정확도가 유지되는가?
   (현재 0.730은 L=0 기준. L=16이면 신호가 약해질 수 있다.)
   → 실패하면 ③이 무너지고 비용 우위가 사라진다.

2. **실측 wall-clock 비교.**
   FOCUS 방식(픽셀 노이즈 + 전체 재인코딩) vs 우리(KV 마스킹 + 층 절단)를
   같은 하드웨어·같은 N에서 TTFT로 비교.
   참고: 3B 이미지 2장 기준 전체 TTFT 실측 510ms.

**이 둘이 나오기 전에는 "FOCUS보다 싸다"고 말하지 않는다.**
