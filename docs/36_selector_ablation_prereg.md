# selector 교체 실험 — 사전 등록

작성 2026-08-25, **측정 전**. 실행 `scripts/40_selector_ablation.py` (job 100091).

## 왜

anchor 벤치에서 우리 컨트롤러가 CLIP보다 약했다 (3B K=2: 0.557 vs 0.817).
그러나 둘의 합집합 상한은 0.907~0.937로, **서로 다른 문항을 맞힌다**(우리만 맞음 27~58건).
그렇다면 진짜 질문은 "누가 더 잘 고르나"가 아니라 **"판별을 남이 해줘도 우리 개입이 이득인가"** 이다.

## 조건 (anchor_items, K∈{2,3}, 3B·7B)

- `CLIP_READ` : CLIP이 고른 것만 남기고 나머지 **읽기만** 차단
- `CLIP_KEEP` : CLIP이 고른 것만 남기고 나머지 **전면** 차단 ← 앞단 selector + 이미지 제거 = 흔한 방식
- `UNION_READ`: CLIP ∪ 우리 선택을 남기고 나머지 읽기 차단

## 판정

| | 조건 | 해석 |
|---|---|---|
| **주 종점** | AUC(CLIP_READ) − AUC(CLIP_KEEP) CI 하한 > 0 | **판별자가 누구든 우리 개입이 이득** — 기여를 '개입'으로 재정의 가능 |
| 부 종점 1 | AUC(UNION_READ) > max(CLIP_READ, REAL_READ) | 두 신호가 상호보완 — 하이브리드가 답 |
| 부 종점 2 | CLIP_READ vs ORD_READ 격차 | 판별 품질이 최종 성능에 얼마나 기여하는가 |

**실패 시**: CLIP_READ ≈ CLIP_KEEP 이면 경로 선택성의 이득이 anchor 벤치에서는 없다는 뜻.
그 경우 경로 선택성 주장의 범위를 위치 참조 벤치로 한정하고 그대로 보고한다.
